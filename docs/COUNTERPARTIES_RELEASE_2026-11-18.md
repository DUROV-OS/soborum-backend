# Контрагенты: первый выпуск, 18.11.2026

## Реализовано

- Единый экран `/suppliers` использует существующий бухгалтерский ID контрагента; закупочный профиль, цены, заказы, MAX и старые API сохранены. Склад видит поставщиков, бухгалтерия — весь справочник в пределах своих прав.
- Карточка с юридическим типом, ИНН/КПП/ОГРН, адресами и отметкой совпадения, директором, несколькими счетами и контактами. Проверки формата, контрольных цифр, дублей и банковского ключа. Старые незаполненные карточки можно дополнять поэтапно; неизменённые старые контакты не блокируют исправление адреса.
- Новые данные хранятся в `counterparty_details` (версия и JSON скалярных полей), `counterparty_bank_accounts` и `counterparty_contacts`. Строки имеют устойчивые UUID; исключённые строки архивируются.
- `counterparty_changes` сохраняет автора, запрос, полные значения до/после и источник; `counterparty_sync_previews` — исходный снимок, его SHA-256, сравнение и автора. PostgreSQL запрещает изменение/удаление истории, все пять таблиц покрыты общим журналом целостности. Это централизованный защищённый журнал, не распределённый блокчейн и не доказательство истинности введённого числа.
- Сохранение проверяет ETag, защищено транзакционными блокировками и ключом идемпотентности. Новый импорт не объединяет контрагентов по одному названию и не заменяет заполненный ИНН либо локальный архивный статус.
- Обновление из МойСклад использует существующий MCP `raw_get` либо Remap token: карточка, все страницы accounts/contactpersons. БИК читается из фактически проверенного поля `bic`. При отсутствии подключения используется явно подписанный сохранённый снимок. Ошибка живого подключения не маскируется старым снимком.
- Сравнение действует 15 минут; заполненные значения не выбраны. Применение повторно проверяет локальную карточку и источник, допускает только выбранные поля. Пакетное заполнение доступно для текущей страницы (20 карточек), через отдельное подтверждение, с последовательными запросами и отчётом ошибок.
- Документы: локальные и импортированные заказы, приёмки, счета-фактуры, исходящие платежи; устранение повторов по source ID, дата/тип, прямые ссылки, CSV/Excel всего отфильтрованного списка. Неизвестная валюта явно указана, общий итог разных типов документов не складывается. Платежи и закупочные документы защищены бухгалтерскими правами.
- Проверку банковских реквизитов выполняет лично назначенный бухгалтер по загруженному документу. Проверяются хеш и размер файла. Изменение версии карточки снимает подтверждение; существующие правила закупочных согласований учитывают этот статус после введения новых реквизитов. Фактические платежи этот выпуск не выполняет.

## API

База `/api/counterparties`: GET/POST список/создание; GET/PATCH `/{id}`; GET `/by-supplier/{id}`; GET `/{id}/history`; POST `/{id}/moysklad/preview`, `/{id}/moysklad/apply`; POST `/backfill/preview`, `/backfill/apply`; GET `/{id}/documents`, `/{id}/documents/export?format=csv|xlsx`; POST `/{id}/verify-bank`.

Основные ответы: 403 нет права записи; 404 нет видимой карточки/сравнения; 409 конфликт версии, идентичности или изменённого источника; 422 ошибки полей; 503 недоступен МойСклад. Ответы не кешируются.

## Границы и следующие задачи

- Совмещение ролей клиент+поставщик и дочерние регистрации/филиалы из расширенной спецификации требуют отдельной миграции; действующее ограничение модели сохранено.
- Экспорт синхронный, без фонового задания для больших объёмов. Документы источника отображаются из имеющегося импорта; отсутствие счёта-фактуры в снимке не означает отсутствие в МойСклад.
- Автоматическое заполнение банка по справочнику БИК, проверка юрлица во внешнем реестре, несколько аккаунтов МойСклад не добавлены.
- Рабочие карточки не перезаписываются при развёртывании. Подтверждение заполнения выполняет сотрудник в интерфейсе.
- Миграция `cparty18112601` только добавляет таблицы и отсутствующие связи поставщика. Downgrade запрещён для сохранения доказательств; резервный выпуск приложения обязан понимать новую версию схемы.

## Проверки

Регрессия API охватывает контакты старых поставщиков, права, оптимистические конфликты, идемпотентность, контроль реквизитов, сравнение источника, пагинацию MCP, ошибки подключения, проверку бухгалтером и повреждение файла. Браузерный сценарий `npm run test:counterparties` использует отдельный in-memory API (не рабочую БД) и проверяет создание, адреса, контакты, сравнение, документы, Excel, ссылки и мобильную ширину 390 px. Перед выпуском миграция и неизменяемость журнала проверяются на изолированной копии PostgreSQL.
