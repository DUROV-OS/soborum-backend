# Основания ответов Марины и планов задач

Общий чат получает данные через инструменты чтения с проверкой прав. Автоматическая общая сводка компании из системного промпта удалена. Запрашиваемая сводка включает только доступные сотруднику разделы; задачи используют область видимости доски. Общая финансовая сводка требует доступа и к клиентам, и к бухгалтерии. Поиск по общей файловой базе знаний доступен администратору, пока для неё нет прав на отдельные документы.

## Что подтверждает запись источника

Успешное чтение сохраняет идентификатор, время, название инструмента, отпечатки аргументов и фактически полученного результата. Модель получает этот идентификатор вместе с данными. Ошибка доступа или ошибка чтения не становится источником.

В конце обычного и потокового ответа сервер добавляет отдельную запись `answer-evidence-v1`: источники текущего запроса, ссылки модели, неизвестные ссылки, наличие прежней истории, внешних результатов, незавершённого ответа, версия модели и отпечатки текста/инструкций. Модель не может самостоятельно прислать эту служебную запись. При повторной отправке истории провайдеру она исключается из контента.

Пользователь может раскрыть сохранённый результат чтения через собственный чат. Сервер сверяет отпечатки аргументов и результата. Изменение прав запрещает выдачу и продолжение чата с прежними основаниями; требуется новый чат. Старые ответы, для которых запись не создавалась, не получают подтверждение задним числом. Источник прошлого запроса не обозначается как свежее чтение.

Совпадение снимка подтверждает его связь с ответом. Оно не подтверждает подлинность первичного документа, правильность расчёта модели или согласование сотрудником. Текущая версия хранит данные в существующем JSON сообщения: это не неизменяемое хранилище и не блокчейн. Выводы не получают автоматическую отметку юридического, бухгалтерского или производственного согласования.

## План дня и приоритеты

Для плана берутся открытые задачи, где сотрудник исполнитель или проверяющий. Дата плана определяется по Москве. Выбор модели ограничивается переданными идентификаторами. Некорректные, выдуманные и повторные идентификаторы, неполный ответ и недоступность модели включают резервный порядок по срокам и приоритетам.

Объяснение формируется кодом из полей карточки, а не из свободного текста модели. Пользователь видит снимок полей задачи, время проверки, число рассмотренных кандидатов, способ выбора и причину резервного расчёта. Внутренние оценки объёма и загрузки не выдаются в ответе API. Их изменение учитывается при сбросе кэша.

Кэш пригоден только при совпадении полного набора кандидатов, сроков, состояния просрочки, ролей в задачах, описаний, приоритетов, зависимостей, внутренней нагрузки, версии алгоритма и модели. После генерации задачи читаются повторно. Если они изменились, старый выбор модели отбрасывается. Ошибка обновления интерфейса скрывает прежний план и не выдаётся за отсутствие задач.

## Проверка качества и оставшиеся ограничения

Автоматические тесты проверяют независимые ожидаемые результаты: разграничение доступа, происхождение снимка, чужой чат, подменённые данные, выдуманную ссылку, ошибку чтения, смену прав, устаревший кэш, изменения во время генерации и московскую дату. Приёмка в браузере использует настоящие API и отдельную базу; вместо платного провайдера — явно заданные тестовые ответы. Эти проверки оценивают защитные механизмы, а не качество реальной модели.

Показатель точности реального ИИ пока не рассчитывается. Для него нужны обезличенные контрольные вопросы с ответами, проверенными Ильёй, Татьяной и руководителем, и отдельные прогоны выбранной модели. Нельзя выдавать прохождение программных тестов за процент правильных бизнес-выводов.

Внешние результаты поиска и удалённой базы знаний обозначаются отдельно; их содержимое не удостоверяется как запись учётной системы. Свободный текст ИИ может содержать ошибочную интерпретацию даже при существующей ссылке. Согласование цены, себестоимости и платежей остаётся в специализированных проверяемых процессах. Для неизменяемой истории ответов и резервных копий требуется отдельное хранилище с политикой сохранения и независимыми контрольными точками.
