# Функциональный переход в Соборум

Критерий готовности — сотрудник выполняет рабочую операцию в Соборуме с тем
же результатом, включая документы, остатки, оплату, историю, архив и права.
Наличие исходного JSON или просмотр перенесённого документа не подтверждает
готовность соответствующей рабочей операции.

Владелец подтвердил 29.10.2026, что Билайн, Wazzup и WhatsApp не используются.
Подключение этих сервисов не является условием перехода. Настроенных
автоматизаций amoCRM почти нет; запрошено развитие контроля лидов с помощью ИИ.

## Проверяемые сценарии этого выпуска

| Сценарий | Поведение и проверка |
| --- | --- |
| Закупка | Создание заказа, позиции, количество, цена, дата поставки, комментарий, архив и защита версии |
| Частичная приёмка | Фактически полученное количество по строкам; остаток заказа и склада меняются вместе; средняя закупочная стоимость обновляется |
| Повтор приёмки | Один UUID запроса проводит документ один раз; другие параметры с тем же UUID отклоняются |
| Параллельная работа | Блокировки PostgreSQL препятствуют превышению количества заказа и потере изменений остатков |
| Оплата частями | Несколько платежей; учёт уже оплаченного и платежей на согласовании; превышение остатка отклоняется |
| История закупок | Исходные заказы и приёмки становятся местными документами без повторного движения запасов и денег |
| Задача продаж | Одна связанная задача видна в CRM и на общей доске; название, описание, срок, ответственный и выполнение синхронизируются |
| Первый контакт | Новая заявка сайта и новая сделка получают контрольную задачу; принятие обращения не теряет эту задачу |
| Контроль лидов | Входящие, просроченные задачи, сделки без шага, срока или ответственного и отсутствие активности рассчитываются из БД |
| Помощь Марины | ИИ читает контроль по причинам внимания и предлагает следующий шаг на согласование; повтор не дублирует задачу и не переносит существующий срок |
| Ответственный | Отсутствующий или отключённый сотрудник попадает в контроль; при назначении шага можно восстановить ответственность за сделку |
| Исторические задачи и KPI | Признак старого выполнения без времени завершения не создаёт выдуманных доказательств для KPI и зарплаты |
| Перемещение | Черновик, проведение между двумя складами, приход и расход в одной транзакции, перенос стоимости; повторы не создают второе движение |
| Инвентаризация | Сохранение учётных остатков и отметки последнего движения; фактическое количество, включая ноль, проводит разницу; движение во время пересчёта останавливает проведение |
| История склада | Одно перемещение и четыре инвентаризации источника становятся историческими документами, архив сохраняется, движения не повторяются |
| Возврат поставщику | На основании проведённой приёмки; количество ограничено полученным за вычетом всех прежних возвратов и фактическим остатком; списание и уменьшение стоимости заказа проводятся вместе |
| Деньги по возврату | Отдельная проводка поступления на согласование; черновики резервируют сумму возврата, поступление уменьшает чистую оплату поставщику, отмена освобождает сумму; складская операция не создаёт поступление денег |
| Ошибочный возврат | Полный доступ к складу и бухгалтерии; после отмены денежных проводок создаётся встречное оприходование, долг восстанавливается; повтор запроса не дублирует отмену, история сохраняется |
| Резерв | Количество закреплено за назначением, домом или строкой перенесённого заказа покупателя; свободный остаток учитывает все резервы; параллельный резерв или расход не могут превысить доступное |
| Использование резерва | Частичное снятие без движения товара; выдача из резерва с документом отпуска; выдача дому по техкарте и заявке сама погашает его резерв, сохраняя чужие |
| Сквозная защита | Свободный остаток проверяется при обычной выдаче, перемещении, списании, возврате поставщику и выпуске по техкарте; частичные действия и повторные запросы сохраняют журнал |
| Пересчёт и резерв | Фактическая инвентаризация может выявить нехватку. Резервы остаются; нехватка показана отдельно. Новые обещания и расходы ограничены реальным свободным остатком |
| Заказ покупателя | Покупатель из общего справочника, организация, товары и услуги, цена к оплате, дата и адрес; черновик, подтверждение, версии, отмена, архив и журнал действий |
| Частичная отгрузка | Черновик не списывает товар. Проведение повторно проверяет остаток каждой строки заказа, реальный склад и чужие резервы; расход и исполнение заказа сохраняются в одной транзакции |
| Резерв заказа | Резерв закреплён за строкой местного заказа. Отгрузка погашает только использованную часть резервов выбранных строк; повторяющиеся товары в других строках и заказы других покупателей защищены |
| Ошибочная отгрузка | Для новой проведённой отгрузки полный доступ к клиентам и складу создаёт встречное оприходование; исполнение заказа восстанавливается, расход остаётся в истории, погашенные резервы не создаются заново |
| История продаж | Восемь заказов и восемь отгрузок из источника связаны через явные ссылки счетов; исходные суммы, исполнение, оплата до переноса и архив сохраняются. Импорт и повтор не создают складских или денежных движений |

По умолчанию первый шаг назначается через 24 часа, контроль отсутствия
активности — через 3 дня. Владелец может изменить правила; существующие сроки
не сдвигаются автоматически. Импорт старой CRM не создаёт по задаче на каждое
историческое обращение: прежняя история доступна для разбора отдельно.

## Оставшаяся приёмка полной замены

- Возвраты покупателей и остальные связанные складские документы.
- Счета покупателям, печатные документы продаж и связь заказов/отгрузок с оплатой.
- Производственные задания, этапы, незавершённое производство и точная себестоимость.
- Взаиморасчёты по всем основаниям, включая приёмки без заказа, авансы и возвраты.
- Редактирование дополнительных полей и прочие используемые операции продаж.
- Реальная доставка формы сайта до карточки и задачи; настройки приёмника и
  безопасный проверочный запрос сами по себе не заменяют такую проверку.
- Финальная сверка изменений после выгрузки и проверка рабочих процессов сотрудниками.

Подписки остаются действующими до завершения этой приёмки. Повторная выгрузка
должна учитывать уже выполненные местные операции: сбросить новые остатки
снимком внешней системы недопустимо.

Возврат поставщику использует цену исходной приёмки для уменьшения долга.
Списание запасов сохраняет текущую среднюю закупочную цену; стоимость списания
зафиксирована отдельно в строке документа. Это не подтверждение партионного
учёта или точной производственной себестоимости. Сводка поставщика пока
охватывает заказы; возврат по приёмке без заказа сохраняет отдельные сумму и
денежные проводки до общей сверки взаиморасчётов. В выгрузке владельца оба
вида возвратов отсутствовали; исторических движений этот выпуск не повторяет.

Резерв не означает выдачу или оплату. Ожидающие заявки производства показаны
отдельно от твёрдых резервов; при оценке закупочной потребности резерв этого
же дома не учитывается второй раз. Выдача по нормативам погашает резервы дома
по порядку создания. Перенесённые заказы стали местными документами; их резервы
перепривязываются без повторного расхода. Для заказа выдача теперь оформляется
отгрузкой, которая сама погашает резерв соответствующей строки.
Выгрузка владельца содержит 8 заказов покупателей и нулевые резервы — это
проверено также по общему отчёту и двум складским отчётам. Миграция создаёт
пустой реестр без изменения остатков и старых документов. Новый внешний
снимок остатков после местных резервов блокируется до согласованной сверки.

Новый заказ не изменяет деньги и остатки. После резерва, черновика отгрузки
или переноса состав, цены и стороны заказа сохраняются; срок, адрес и
комментарий можно уточнить. Отгрузка со складов оформляется отдельными
документами для каждого склада. Отмена новой отгрузки восстанавливает запас
по зафиксированной средней стоимости списания, с пересчётом текущей средней
цены; это не подтверждение точного партионного/FIFO учёта.

Проведённые исторические отгрузки нельзя проводить или отменять повторно:
их исполнение включено в начальное состояние заказа, а запас уже перенесён
общим снимком. Новые платежи по заказам, новые счета, документы возврата
покупателя и их денежные последствия ещё требуют отдельного выпуска.
Девять исходных счетов остаются в сохранённом реестре источника. Показатель
«Оплачено до переноса» не складывается повторно с импортированными платежами.
